# Frontend architecture and route inventory

## Rendering model

The App Router uses Server Components by default. Marketing pages are primarily server-rendered compositions. Admin pages, chat, maps and playground games are Client Components. Insights list/detail are async Server Components. Dynamic imports isolate game components; Google Maps is loaded in the browser. `next/font`, metadata, sitemap and robots are implemented. Images are mostly ordinary `<img>`/CSS URLs rather than a consistent `next/image` pipeline.

## Public routes

| Route | Purpose | Data/runtime |
| --- | --- | --- |
| `/` | Sectioned studio homepage | local data/components |
| `/about`, `/services`, `/technologies`, `/team`, `/pricing`, `/faq`, `/contact` | Studio information and contact entry points | local data; contact form posts inquiry BFF |
| `/projects` | Portfolio list | local data |
| `/projects/[slug]` | Published project case study | `data/cmsData.json` snapshot |
| `/portfolio` | Alias for projects | component re-export |
| `/work/[slug]` | Alias for project detail | component re-export |
| `/insights` | Published articles and filtering | Express with local fallback |
| `/insights/[slug]` | Article, metadata and related posts | Express with local fallback |
| `/blog` | Redirect/alias to Insights | Next redirect page |
| `/careers` | Jobs and internships presentation | local careers data |
| `/playground` | Game index | server page |
| `/playground/code-breaker` | Code-breaking game | client-only game |
| `/playground/bug-hunt` | Bug-finding game | client-only game/local data |
| `/playground/logic` | Logic puzzles | client-only game/local data |
| `/privacy-policy`, `/terms` | Legal content | static |

`/sitemap.xml` and `/robots.txt` are generated by `app/sitemap.ts` and `app/robots.ts`. Global metadata hard-codes `https://olinethra.com`; dynamic Insight metadata uses stored SEO fields.

## Admin routes

| Route | Intended capability | Effective backend permission |
| --- | --- | --- |
| `/admin` | Counts, recent inquiries, activity | any authenticated role can read the full admin CMS export |
| `/admin/login`, `/admin/activate`, `/admin/forgot-password`, `/admin/reset-password` | Authentication lifecycle | public |
| `/admin/projects`, `/admin/team`, `/admin/services`, `/admin/faqs`, `/admin/chatbot` | Content CRUD | Super Admin or Content Admin via CMS service checks |
| `/admin/internships`, `/admin/hiring`, `/admin/applications` | Hiring CRUD/status | Super Admin or Hiring Admin via CMS checks |
| `/admin/inquiries` | Inquiry status/priority | Super Admin only (not in delegated role allowlists) |
| `/admin/settings` | Site/location settings | Super Admin only |
| `/admin/insights`, `/new`, `/ai-create`, `/tech-briefs`, `/categories`, `/[id]/edit` | Insight workflow | Super Admin or Content Admin, except category GET is any authenticated role |
| `/admin/whatsapp` | Conversations, messages, handoff, lead editing, metrics | any authenticated role; two data URLs currently return 404 |
| `/admin/quotes`, `/upload`, `/[id]` | PDF archive | Super Admin and Content Admin; deletion Super Admin only |
| `/admin/analytics/ml` | Readiness, scoring and retraining | any authenticated role |
| `/admin/users` | Admin membership and roles | Super Admin through `users` permission |
| `/admin/media` | Media-library UI | no registered backing media API; UI is partial |

Admin navigation is not filtered by role. Unauthorized actions fail at the API/CMS service layer; several authenticated-only APIs (CMS export, WhatsApp, quotes and ML) are broader than the navigation’s implied domain roles.

## Component groups

- `components/layout` and root-level `Navbar`/`Footer`: public shell.
- `components/sections` and `components/home`: landing and feature sections.
- `components/admin/AdminLayout`: authentication check, navigation and admin shell.
- `components/chat/Chatbot`: site-wide assistant calling `/api/chat`.
- `components/maps`: browser map and admin coordinate picker.
- `components/playground`: game state and UI; browser-only, no backend.
- `components/insights`: authorship and audience presentation.
- `components/ui`: reusable Radix/shadcn-style primitives and WhatsApp CTA.

## Performance, SEO and accessibility observations

Implemented performance measures include Server Components for most public pages, Next font loading, dynamic game imports, no-store admin/BFF calls, API pagination for Insights and quotes, and lazy browser map loading. No explicit Next revalidation policy or CDN cache layer is present.

Metadata, Open Graph/Twitter metadata, sitemap, robots and dynamic Insight metadata are implemented. Canonical handling is inconsistent: the root layout declares `/` globally, while stored Insight canonicals may be relative. Accessibility primitives support focus/keyboard behavior, and many pages use semantic headings/labels. No formal WCAG audit or automated accessibility test exists, so compliance is not claimed.
